# Платёжные адаптеры

`fragment_bot/payments.py` содержит контракт `PaymentGateway` и общую обработку `Checkout`. Сейчас есть адаптеры `TelegramStarsGateway` и `DemoGateway`. Поля `name` и `currency` сохраняются в заказе вместе с суммой в минимальных единицах, покупателем и получателем. Бот принимает XTR для цифровых товаров в соответствии с [Bot Payments](https://core.telegram.org/bots/payments-stars).

Для нового адаптера в собственном разрешённом канале продаж:

1. Реализуйте `PaymentGateway`. `checkout(order)` создаёт счёт для неизменяемого заказа. В ключе идемпотентности на стороне провайдера используйте `order.id`. `refund(buyer, charge_id)` выполняет возврат исходного платежа и одинаково обрабатывает успешный ответ и уже выполненный возврат.
2. Создайте `Checkout(store, gateway)` в точке входа нужного канала. Сохраните заказ через `Checkout.create`. Зарезервируйте платёж через `Checkout.authorize` с уникальным идентификатором попытки, покупателем, суммой и валютой. При отказе завершите оформление этого счёта.
3. Во входящем обработчике проверьте подпись по официальной спецификации провайдера и конечный статус платежа. Где применимо, запросите платёж по его ID у провайдера и сверяйте результат. Передайте в `Checkout.capture(PaymentReceipt(...))` только подтверждённый платёж. Подтверждайте входящее уведомление после фиксации в базе. Возврат покупателя на страницу успеха сам по себе не подтверждает оплату.
4. `capture` атомарно сверяет покупателя, идентификатор заказа, провайдера, валюту и сумму с сохранённым заказом. Повторный `charge_id` для того же провайдера не меняет состояние. Неподходящие платежи остаются в `payment_exceptions` для ручной сверки.
5. Выдача проходит через `Store.approve`, `Store.claim` и `Fulfillment.deliver`. Платёжные вебхуки и повторные уведомления не запускают списание с TON-кошелька. Для возврата передайте в `Fulfillment.refund` адаптер, указанный в заказе.

Тесты нового адаптера должны покрывать валидный платёж, неверную подпись, несоответствие суммы/валюты, повторы и возврат. Для XTR подлинные обновления читаются через Bot API, поэтому webhook-сервер для штатной установки не нужен.

## Сверка

`payment-errors` выводит исходные идентификаторы платежей для оператора. Если Telegram списал XTR по платежу из списка исключений, сверьте его по `charge_id` и покупателю. Возврат выполняется командой `refund-payment-error CHARGE_ID`. Заказы на проверке после попытки выдачи содержат ID операции SDK. Журнал в той же SQLite-базе сохраняет связанный подписанный пакет до отправки. Его следует хранить приватно вместе с базой.
